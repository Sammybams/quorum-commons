# Quorum WhatsApp Gateway

Small Baileys-based bridge used only for Quorum WhatsApp group sync.

Environment variables:

```text
HOST=127.0.0.1
PORT=3001
WHATSAPP_GATEWAY_TOKEN=
WHATSAPP_AUTH_ROOT=
QUORUM_API_BASE_URL=http://127.0.0.1:8000/api/v1
QUORUM_WHATSAPP_CHANNEL_ID=
QUORUM_WHATSAPP_CHANNEL_SECRET=
```

What these values mean:

- `QUORUM_WHATSAPP_CHANNEL_ID`: the numeric WhatsApp channel ID generated by Quorum after you click `Prepare WhatsApp` in `Settings -> Integrations`. It tells the gateway which Quorum channel record to send messages into.
- `QUORUM_WHATSAPP_CHANNEL_SECRET`: the shared secret generated by Quorum for that channel. The gateway sends it as `x-quorum-channel-secret` so the backend knows the request really came from your gateway.
- `WHATSAPP_GATEWAY_TOKEN`: any private string you choose for your own machine, for example `quorum-local-dev-token`. It protects the gateway's `/internal/*` routes.
- `WHATSAPP_AUTH_ROOT`: the local folder where this Quorum gateway stores its Baileys session files. Use a Quorum-specific path such as `/Users/sam/Documents/quorum-commons/whatsapp-gateway/.auth`.

Recommendation:

1. Do not reuse the Sales Prospecting auth folder here. The session files are app-specific and you do not want the two tools sharing or overwriting each other's WhatsApp state.
2. Reusing the same internal token is technically possible, but it is cleaner to use a separate token for Quorum.

Install and run:

```bash
cd whatsapp-gateway
npm install
npm start
```

Quorum setup flow:

1. Start the Quorum backend and frontend first.
2. Open `Settings -> Integrations` inside the target workspace.
3. In the `WhatsApp` card, click `Prepare WhatsApp`.
4. Copy the generated `channel id`, `inbound URL`, and `gateway secret` from the channel card.
5. Set `QUORUM_API_BASE_URL`, `QUORUM_WHATSAPP_CHANNEL_ID`, and `QUORUM_WHATSAPP_CHANNEL_SECRET` in the gateway environment.
6. Start the gateway.
7. Call the internal connect endpoint to start QR or pairing-code login.
8. Add the connected WhatsApp account to the groups you want available for review.
9. Return to `Settings -> Integrations` in Quorum and enable sync only for the approved groups.

Example local environment:

```text
HOST=127.0.0.1
PORT=3001
WHATSAPP_GATEWAY_TOKEN=dev-token
WHATSAPP_AUTH_ROOT=/absolute/path/to/quorum-commons/whatsapp-gateway/.auth
QUORUM_API_BASE_URL=http://127.0.0.1:8000/api/v1
QUORUM_WHATSAPP_CHANNEL_ID=12
QUORUM_WHATSAPP_CHANNEL_SECRET=replace-with-secret-from-quorum
```

Example connect requests:

QR login:

```bash
curl -X POST http://127.0.0.1:3001/internal/session/connect \
  -H 'content-type: application/json' \
  -H 'x-internal-token: dev-token' \
  -d '{"pairingMode":"qr"}'
```

Pairing-code login:

```bash
curl -X POST http://127.0.0.1:3001/internal/session/connect \
  -H 'content-type: application/json' \
  -H 'x-internal-token: dev-token' \
  -d '{"pairingMode":"pairing_code","phoneNumber":"2348012345678"}'
```

Check session state:

```bash
curl http://127.0.0.1:3001/internal/session \
  -H 'x-internal-token: dev-token'
```

Privacy behavior:

1. The linked WhatsApp account can see chats at the device layer once it joins them.
2. Quorum only persists and processes messages from groups explicitly enabled in the workspace.
3. Unselected groups are discovered for review and ignored during sync.
4. Removing group sync in Quorum stops new messages from that group from being forwarded into the platform.

Internal endpoints:

- `GET /health`
- `GET /internal/session`
- `POST /internal/session/connect`
- `POST /internal/session/disconnect`

All `/internal/*` routes require `x-internal-token` when `WHATSAPP_GATEWAY_TOKEN` is set.
